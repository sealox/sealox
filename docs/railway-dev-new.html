Railway dev.new 完整技术方案

结论已经齐了：dev.new 不是「Agent 写完代码再手写 Dockerfile 部署」。 它是两台机器——一台常驻 Ubuntu 开发 VM 里跑编码 Agent；一次 ship 只上传源码，由 Railpack 另编生产镜像。

证据：官方长文、Cloud Agents / Sandboxes / Railpack 文档、项目 Pricing Page 的构建日志与线上站点。 未公开的实现会单独标出，不当成事实。

结论 架构 三种 Agent 第一台 VM 发布路径 生产底镜像 一次会话 实测 未公开 如何抄

1. 结案：三句话

对的部分 先开一台绑定在用户项目上的 VM，里面预装 Web 开发环境；Agent 在 VM 里面写 /app；8080 热更新预览；满意后再发到 Railway。
必须改掉的理解 写完打包 → 写 Dockerfile → 部署。 实际是 ship 上传源码快照（Pricing Page 这次 2.6 MB，不含 node_modules），Railpack 自动检测并构建。生产底是瘦 Debian，不是那台 Ubuntu 开发机。
你原来的说法实际机制
一台 VM / 容器里写代码再部署开发 VM 和生产服务是两个运行时。生产是另一次构建。
Agent 远程操控这台机器编码 Agent 是机内进程，cwd 在 /app，像本地开发者。
「那个 Agent」是一个东西至少三个产品共用 Agent 这个词，见第 3 节。
第一台 VM ≈ railpack-runtime开发机是肥 Ubuntu；生产底是 debian:bookworm-slim + 5 个包。

2. 总架构：两平面

左边是给人看草稿的电脑，右边是给用户访问的网站。中间没有 Dockerfile 作者。

草稿 · Studio / Cloud Agent VM

第一条 prompt 在用户 workspace 建项目，启动完整 VM（和 Sandboxes / Cloud Agents 同一套原语）。/app 预装 Vite + React 19 + Tailwind v4，dev server 已在 8080。磁盘可挂回，空闲休眠。

发布 · 普通服务

ship 在同一项目创建/更新服务 web，上传 /app。Railpack 识别、安装、构建、决定启动命令，分配 *.up.railway.app。生产里没有 Agent，没有 Vite。

3. 「Agent」其实是三个产品

railway-agent 这个词被复用了。dev.new 用的是机内写代码的那个，不是仪表盘运维机器人。

5. 发布路径：ship → Railpack，没有 Dockerfile

ship 等于「记住服务 ID 的 railway up」：

  1. 第一次在同一项目创建服务（Pricing Page 叫 web）并记住 ID；之后更新同一服务。
  2. 打包 /app 源码。实测快照 sha256:60925b9d…，2.6 MB，未含 node_modules。
  3. Railpack 0.36.4 在 builder 镜像里检测：Node + npm；Vite 静态站；output = dist。
  4. 构建：npm install → npm run build（Vite 8.2.1）→ 把 dist 拷进 runtime。
  5. 启动：caddy run --config /Caddyfile（Caddy 2.11.4 由 mise 在构建层安装后拷入）。
  6. 分配公网域名。下一轮 ship 更新同一服务。

若应用是带 WebSocket 的长驻服务（长文 FPS demo），Railpack 会走 Node start，而不是 Caddy。检测看源码形态，不看 Studio 模板。

预览域名 ≠ 生产域名 Studio VM 自己有公网入口（Agent 用 curl + Host 和 Playwright 打的就是它）。生产是独立服务，例如 web-production-5dc653.up.railway.app。空闲后开发 VM 会睡/回收；生产服务继续在。

6. 生产底镜像 ghcr.io/railwayapp/railpack-runtime:mise-2026.8.4

这是 Railpack 最终容器的底，不是开发 VM。tag 里的 mise 是版本钉（与 Railpack 0.36.4 锁定的 mise 2026.8.4 对齐），runtime 里没有 mise。mise 在 builder 镜像里，构建完丢掉。

10. 要抄就抄这三块

不要做一个「又能热更新又能当生产」的容器。

  1. 控制面：开 VM、挂盘到 /app、把 :8080 反代成预览域名、点击映射成 file:line。
  2. 开发镜像：Ubuntu + Node 24 + Chromium/Playwright + 机内编码 harness + 预烤 Vite 脚手架。Agent 禁止重启预览进程。空闲停机留盘，不要删 VM。
  3. ship：上传源码（不含 node_modules），用 Railpack/Nixpacks 另一次构建。Vite 静态站 → dist + Caddy/nginx；有服务端 → 跑 Node。
# 生产底的等价物就是官方 runtime Dockerfile，不必自研
FROM debian:bookworm-slim
