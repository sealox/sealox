# Helios 0.6 — database

相对 [vision](./vision.md) / [0.1](./0.1-baseline.md) / [0.4](./0.4-operate.md) / [0.5](./0.5-topology.md)：数据库从「一张不能点的卡片」变成能看见、能连、能对实例动手的详情页。不把 Sealos dbprovider 的八个 tab 搬进来。

包版本 `0.6.0`。

## 相对现状的缺口

0.1 数据库 tab 只列 KubeBlocks Cluster：名字、引擎、版本、阶段、所属项目。0.4 能随项目 pause/start/restart，独立库没有按钮。0.5 拓扑上库节点「点了不跳」。用户没法回答：里面有什么、怎么连、我能对它做什么。

## 已拍板（不要再改）

1. **密码**：Vercel 同款。默认打码，点一下揭开。复制走明文。
2. **里面有什么**：页上只读列出逻辑库名和 table / collection 名。不做 SQL 输入、不做行编辑、不做 dump/导入、不嵌 Dataflow。大改走用户自己的 GUI 或「问 Helios」。
3. **范围**：连接 + 实例操作 + 被谁用 + 健康/Pods/事件 + **schema 目录 + 公网开关**，同一版做完。
4. **问 Helios**：按钮切到「开始」、开新对话、输入框预填这段库的上下文，不自动发送。清单回答一眼，查询交给 agent。

Vision「数据库只展示 secret 名」对列表/项目详情仍然成立。本版详情页是例外：连接就是这页的工作。

## 用户看见的流程

### 入口

- 数据库 tab 卡片可点，进详情（tab 归位到「数据库」）。
- 项目拓扑的数据库节点可点，进详情（栈上保留项目，能返回）。
- 项目详情若还有库的文字入口，同样进详情。

存储桶仍然不进详情。

### 详情（一页滚到底，对齐应用详情，不要 tab 栏）

**顶栏**：名字、引擎 chip、阶段点、所属项目 chip（点回项目）。暂停或启动、重启、删除。删除弹框，重启/暂停不二次确认（与 0.4 应用相同）。进行中禁用。属于某项目的库，确认框写明是项目的一部分、删库可能让应用连不上，并给「去项目」。

**问 Helios**：顶栏按钮。切到「开始」，`startNewChat`，输入框填入（可改、不发送）：

```
请查看当前工作空间的数据库 {name}（引擎 {engine}，版本 {version}，状态 {phase}）。先不要改数据。我的问题是：
```

光标落在末尾。

**统计条**：状态、引擎+版本、CPU/内存限额、存储、创建时间。

**连接（主角）**：

- 集群内 host / port / username / password / connection string。
- 密码和 URI 默认打码（`••••••••`）；点「显示」揭开，再点收起。
- 每项可复制明文（即使当时是打码状态）。
- 给一段 `DATABASE_URL`（或该引擎等价）环境变量示例，风格对齐 AI Proxy 接入卡，复制即用。
- 未 Running 或 secret 还没有：写明「凭证尚未就绪」，不要假 URI。

**公网**：开关。关着只显示内网。打开后出现公网 host/port（或 Sealos 返回的 publicConnection），同样打码/揭开/复制。打开公网是明确动作，失败钉在这页。

**被谁使用**：本工作空间里 env 已证实引用该库的应用（复用 0.5 `topology.ts` 的规则，作用域换成「这一份库」）。点应用进已有应用详情。一个都没有就写「没有应用通过环境变量引用它」，不要猜。

**结构**：逻辑库列表；每个库下列 table/collection 名。只读。点名字不要打开编辑器、不要跑 SQL。引擎不支持（Redis / Kafka / 向量库等，以 Sealos `getDatabases` 实际报错为准）：一句话「此引擎不列出表结构」+ 问 Helios。库未 Running：不 exec，提示先等它就绪。

**健康**：近 1 小时 CPU / 内存 / 磁盘曲线，对齐应用详情 SparkCard。磁盘溢出（Sealos `isDiskSpaceOverflow`）用横幅，不要另做监控 tab。

**Pods + 事件**：和应用详情同一套展开/日志尾部/Warning 标红。

15 秒刷新详情；监控 60 秒。切工作空间清空栈。

### 列表

卡片可点。本版不做数据库 tab 的批量、不做列表上的暂停/删除（避免和 0.4「数据库 tab 没有批量」打架）。操作在详情顶栏。

## API（对着 Sealos 源码，不发明）

源码：`dev-assets/sealos/frontend/providers/dbprovider`（没有则按 `.cursor/rules/sealos-source.mdc` 补 sparse checkout）。鉴权与 0.3/0.4 相同：`Authorization: encodeURIComponent(kubeconfig)`。区域 host 优先 `auth.json` 的 `region`。超时：详情/监控 15s 量级，pause/start/restart/delete/公网 120s。

实现时对照源码，不要凭这份摘要硬编字段名。尤其 `publicConnection` 在 schema 里写成 `string | null`，以 `get-database.ts` 运行时组装为准。

| 动作 | 方法 | 路径 |
|---|---|---|
| 详情（含连接、pods、quota、状态） | GET | `https://dbprovider.{region}/api/v2alpha/databases/{name}` |
| 删除 | DELETE | 同上（204；404 当成功） |
| 暂停 / 启动 / 重启 | POST | `.../databases/{name}/pause\|start\|restart` |
| 开/关公网 | POST | `.../databases/{name}/enable-public` / `disable-public` |
| 监控 | GET | `.../api/v2alpha/monitor/data?dbName&dbType&queryKey=cpu\|memory\|disk` |
| 逻辑库名 | POST | `https://dbprovider.{region}/api/db/getDatabases` body `{ dbName, dbType }` |
| 表名 | POST | `.../api/db/getTables` body `{ dbName, dbType, databaseName }` |

后两条是 Sealos 控制台仍在用的 BFF（内部 exec 进 `{name}-{component}-0`），**不是** v2alpha。响应是 `{ code, data, error }`，不要用 v2alpha 的 `{ error: { type, code } }` 去解。只对 postgresql / mysql / apecloud-mysql / mongodb 调；其它引擎不要打这条再把 500 丢给用户。

`dbType` 用 Cluster 的 `clusterDefinitionRef` / 标签，和 Sealos `DBTypeEnum` 对齐（MySQL 常常是 `apecloud-mysql`）。

pause/start/restart 已在 `operate.ts` 里给项目用，**导出**给独立库 IPC，不要复制一份 HTTP。

错误体映射短文案（登录失效 / 没有权限 / 不存在 / 服务暂不可用 / 该动作失败），不要把整段 JSON 丢给用户。

## 工程落点

做事在 Electron **主进程**，渲染进程不直连 Sealos。

- 新文件 `apps/electron/src/main/sealos/database.ts`：GET 详情、监控、schema（getDatabases + 每个库 getTables）、enable/disable public。连接明文只走这条详情 IPC，不要写进 `ResourceSnapshot`。
- `operate.ts`：导出 `pauseDatabase` / `startDatabase` / `restartDatabase`，补 `deleteDatabase`（DELETE v2alpha，404=成功）。
- 「被谁使用」：复用 `topology.ts` 的证实规则，对当前 ns 的 Launchpad 工作负载扫这一份库；不要新 Sealos 路径。
- IPC / preload / `HeliosApi`：`getDatabaseDetail`、`getDatabaseMonitor`、`getDatabaseSchema`、`pauseDatabase` / `startDatabase` / `restartDatabase` / `deleteDatabase`、`enableDatabasePublic` / `disableDatabasePublic`。参数就是名字（schema 的 getTables 在主进程内做完，渲染进程拿回树，不要让渲染进程循环打 IPC）。
- 渲染：`DatabaseDetailView` 对齐 `AppDetailView`（`detailParts` / `.daction` / 统计条 / SparkCard / Pod 行）。`ResourcesScreen` 的 `DetailEntry` 增加 `{ type: 'database'; name: string }`。拓扑 `onNodeClick` 对 database 节点打开详情。
- 「问 Helios」：`HomeChat` 增加可选草稿（例如 `composerDraft` + `draftKey`）。收到新 key 时 `startNewChat` 并 `setText`。不要改 eve、不要新 IPC。
- 密码揭开是渲染进程本地 state，不要为揭开再打 IPC。
- 根和 `@helios/electron` 的 `package.json` version 改为 `0.6.0`。`docs/versions/vision.md` 版本记录补上 0.6。

## 本版明确不做

- SQL 输入框、Query tab、行编辑/插入/删除、spreadsheet
- Dataflow / phpMyAdmin / 在 app 内连上跑查询
- 创建库表单、YAML、PATCH CPU/内存/副本/参数
- Dump 导入、跨网迁移、备份恢复向导（连「上次备份时间」都可以没有）
- 数据库 tab 批量；存储桶详情
- 改 0.2 对话协议、0.3 模板部署

## 验收

- 数据库列表卡片能点进详情；拓扑库节点能点进详情；从项目进来能返回项目。
- Running 的 pg/mysql/mongo：能看见打码的连接串，点一下揭开，复制得到明文；能看见逻辑库和表名。
- Redis/Kafka：详情和连接仍在，结构区说明不列出表，不报一长串 500。
- 暂停/启动/重启/删除打的是 dbprovider v2alpha；属于项目的删除确认提到项目。
- 公网开关能开能关；开了之后出现公网地址（Sealos 返回了的话）。
- 「问 Helios」落到开始页新对话，输入框含库名，没有自动发出去。
- 切工作空间后按钮打到新空间。进行中不能连点出两次请求。
- `npm run typecheck -w @helios/electron` 通过。
