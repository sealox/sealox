# Helios 0.4 — operate

相对 [vision](./vision.md) / [0.1](./0.1-baseline.md) / [0.2](./0.2-agent-chat.md) / [0.3](./0.3-templates.md)：项目和应用从「只读看见」变成能做确定动作——删除、重启、暂停/启动。配置类变更（镜像、副本、环境变量）仍走「开始」对话。

已完成，2026-08-15。包版本 `0.4.0`。

## 相对 0.1 的缺口

0.1 列表和详情已经能看见项目 / 应用。动作只剩对话。0.1 把「以项目为单位的整体删除（需二次确认）」留给后续。

删除、重启、暂停是用户已经决定要做的事。点按钮比再打一遍字更准。0.3 模板「部署」已经是这条路。

## 模型

- **应用**：原子。带 `cloud.sealos.io/app-deploy-manager` 标签的 Deployment / StatefulSet（与 App Launchpad 同一口径）。
- **项目**：一个或多个应用的集合，外加数据库 / 存储桶。对应 namespace 里的 `instances.app.sealos.io` CR，归属 `cloud.sealos.io/deploy-on-sealos=<instance>`。
- **项目级重启 / 暂停 / 启动**：没有实例级 API。Helios 对名下每个 Launchpad 应用打 applaunchpad，对名下每个 KubeBlocks 数据库打 dbprovider。对象存储没有暂停接口，不动。定时任务不操作。
- **Launchpad 之外的工作负载**：没有 applaunchpad 这套 API。本版不提供删 / 重启 / 暂停 / 启动，避免另造协议。

## 用户看见的流程

### 列表

项目卡片、Launchpad 应用卡片右上角有「删除」。点删除不进详情。点卡片其它区域仍进详情。

### 批量（仍是列表，不是新页）

只在**项目** tab 和 **应用** tab 的 Launchpad 卡片上多选。两个 tab 的选择互不相干，不能混在一次操作里。数据库 / 存储 / Launchpad 之外的工作负载没有勾选。

每张可操作卡片左侧加勾选框，点勾选不进详情。点卡片其它区域仍进详情。

选中 ≥ 1 条时，列表标题行下方（或页头）出现操作栏：已选 N 个 · 全选 / 取消选择 · 暂停 · 启动 · 重启 · 删除。切 tab、切工作空间后清空选择。

混选时按钮按集合出：有不是「已暂停」的就出暂停，有「已暂停」的就出启动，重启和删除一直在。暂停只打还在跑 / 处理中的；启动只打已暂停的；重启打全部选中项。项目的暂停/启动/重启语义与单条相同（应用 + 数据库）。

删除仍弹框，**一次确认整批**，不要 `window.confirm`：

| 对象 | 文案要点 | 主按钮 |
|---|---|---|
| 多个项目 | 将删除 N 个项目；合计带走 X 个应用、Y 个数据库、Z 个存储桶；不可恢复。列出选中项目的备注名（多了截断 +「等 N 个」） | 删除 N 个项目 |
| 多个应用 | 将删除 N 个应用；不可恢复。若其中有属于项目的，写明「其中 M 个是项目的一部分，只删应用、不拆项目」（一批里可能跨多个项目） | 删除 N 个应用 |

批量删除不再为每一条提供「去项目」。单条删除的「去项目」路径保留。

进行中整栏禁用，防连点。逐个调用已有单条 IPC（`pauseProject` / `pauseApp` 等），**不发明** Sealos `/batch` 接口。某个失败：已成功的不回滚；失败名单钉在操作栏；选择保留（便于重试失败项）；快照仍刷新，避免已删掉的还留在列表。全部成功：关栏、清空选择、刷新快照。

详情页保持单条操作，不在详情里多选。

### 详情顶栏

项目详情、Launchpad 应用详情：删除、重启、暂停或启动。重启 / 暂停 / 启动不二次确认——点按钮就是确认。删除一律弹框。

应用已暂停（或状态为已暂停）时顶栏显示「启动」，否则显示「暂停」。项目名下有的在跑、有的停着：暂停和启动可以同时出现。暂停：先应用后数据库；启动：先数据库后应用。项目里既没有 Launchpad 应用也没有数据库时，只留删除。

### 删除确认（弹框，不要 `window.confirm`）

| 对象 | 文案要点 | 主按钮 | 另给一条路 |
|---|---|---|---|
| 项目 | 显示备注名和实例名；写清将带走 N 个应用、N 个数据库、N 个存储桶；不可恢复 | 删除项目 | 取消 |
| 独立应用（无项目归属） | 确定删除「名字」；不可恢复 | 删除应用 | 取消 |
| 属于某项目的应用 | 「X」是项目「Y」的一部分。只删这个应用，项目里的数据库和其它应用还在。要拆整个栈，走项目删除 | 只删除这个应用 | 「去项目」打开该项目详情（再由用户自己点项目删除） |

进行中禁用按钮；失败钉在弹框里，人不走。成功：关弹框、刷新资源快照；若当前正在看被删的那条详情，退回列表（或项目详情，如果删的是项目里的一个应用且栈上还有项目）。

### 重启 / 暂停 / 启动

按钮立刻进入「…中」并禁用同类动作，防连点。失败钉在详情页。成功后刷新该详情和资源快照（已有 15s 轮询，不要另做进度页）。

## API（对着 Sealos 源码，不发明）

源码以本机 `/Users/che/Documents/GitHub/sealos` 为准。实现时对照，不要凭这份摘要硬编字段。鉴权与 0.3 模板部署、applaunchpad 监控相同：`Authorization: encodeURIComponent(kubeconfig)`。区域 host 优先 `auth.json` 的 `region`，再回退 kubeconfig hostname（与 0.3 相同，避免 `apiserver.*` 拼错）。超时 120s 量级。

### 应用（App Launchpad v2alpha）

实现：`frontend/providers/applaunchpad/src/pages/api/v2alpha/apps/[name]/`

| 动作 | 方法 | 路径 | 成功 |
|---|---|---|---|
| 删除 | DELETE | `https://applaunchpad.{region}/api/v2alpha/apps/{name}` | 204（文档：不存在也 204） |
| 重启 | POST | `.../apps/{name}/restart` | 204 |
| 暂停 | POST | `.../apps/{name}/pause` | 204（已暂停也 204） |
| 启动 | POST | `.../apps/{name}/start` | 204（未暂停也 204） |

删除只拆这一个 Launchpad 应用；StatefulSet 的 PVC 默认留下（Sealos 文档如此）。Helios 不要自己再去删 PVC。

错误体：`{ error: { type, code, message, details? } }`。按 HTTP 状态 + `error.code` 映射到短文案（登录失效 / 没有权限 / 不存在 / 服务暂不可用 / 该动作失败），不要把整段 JSON 丢给用户。

### 项目（Template instance）

实现：`frontend/providers/template/src/pages/api/v2alpha/templates/instances/[instanceName].ts`。skill 的 `sealos-api.py delete` 就是这条。

| 动作 | 方法 | 路径 | 成功 |
|---|---|---|---|
| 删除 | DELETE | `https://template.{region}/api/v2alpha/templates/instances/{name}` | 204 |

会扫掉实例标签下的应用、数据库、存储、PVC。Helios 不要自己再扫一遍资源。404（实例已不在）当成功，删除幂等。

Template 没有实例级 restart / pause / start。项目这三件事：

1. 列出当前 ns 里同时带 `cloud.sealos.io/deploy-on-sealos=<instance>` 和 `cloud.sealos.io/app-deploy-manager` 的 Deployment / StatefulSet（排除 `app.kubernetes.io/managed-by=kubeblocks`）。
2. 列出同一归属标签的 KubeBlocks `Cluster`。
3. 暂停：先应用 `POST .../apps/{name}/pause`，再数据库 `POST https://dbprovider.{region}/api/v2alpha/databases/{name}/pause`（已 Stopped/Stopping 的库跳过）。启动相反：先库后应用（已 Running/Starting 的库跳过）。重启：应用全部 + 未停止的库。
4. 有失败：报出失败的组件名和原因；已成功的不回滚。名下没有应用也没有数据库：直接成功。

列表用现成 `@kubernetes/client-node`，不要为了列名字再发明 BFF。鉴权与应用相同：`Authorization: encodeURIComponent(kubeconfig)`。成功 204。

项目聚合状态优先级：异常 > 处理中 > 运行中 > 已暂停。应用停了但数据库还在跑，项目就是运行中——所以暂停必须把库一起停掉。KubeBlocks 停库是异步的（Running → Stopping → Stopped），过渡态显示「处理中」，不要显示「运行中」。

## 工程落点

做事在 Electron **主进程**，不经过 eve。

- 新文件 `apps/electron/src/main/sealos/operate.ts`：应用四动作 + 数据库 pause/start/restart + 项目删除 + 项目三动作（应用 + 数据库）。HTTP 风格对齐 `templates.ts`（kubeconfig 头、v2alpha 错误体、120s）。
- IPC / preload / `HeliosApi` 暴露：`deleteApp` / `restartApp` / `pauseApp` / `startApp` / `deleteProject` / `restartProject` / `pauseProject` / `startProject`。参数就是名字。
- 渲染：列表卡片删除；详情顶栏四个动作；项目/应用列表勾选 + 批量操作栏。共用已有确认弹框。卡片勾选和删除都 `stopPropagation`，避免误进详情。批量在渲染进程对选中名字逐个调已有 `window.helios.*`，不要新 IPC、不要新 Sealos 路径。
- 样式跟现有 `.daction` / `.btn-neutral` / 卡片走，危险操作用红，不要新主题。
- 根和 `@helios/electron` 的 `package.json` version 改为 `0.4.0`。

仓库里若已有半成品，按本文改到能过 typecheck，不要另起一套协议。

## 本版明确不做

- 应用 / 项目的配置表单（`PATCH /apps/{name}`：镜像、CPU、副本、端口、环境变量）
- 数据库、存储桶的单独删除 / 暂停 / 重启（库随项目暂停/启动/重启/删除走；桶随项目删除走）
- Launchpad 之外工作负载的任何变更
- 删除前的 agent 确认、失败自动拉起排障对话
- 改 0.2 对话、改资源信息架构、改模板部署
- 项目和应用放进同一次选择；跨工作空间批量；数据库/存储列表批量

## 验收

- 项目列表卡片能删；确认框写清会带走的应用 / 数据库 / 存储桶数量；确认后列表里没有它，工作空间里 Instance CR 和名下资源按 Sealos 删除语义消失。
- Launchpad 应用列表卡片能删；无项目归属的确认是简单不可恢复；有项目归属的确认写明是项目的一部分，并提供「去项目」。
- Launchpad 之外那一截没有删除按钮，详情也没有重启 / 暂停 / 启动 / 删除。
- 应用详情：重启会滚动重建 Pod；暂停后状态变已暂停；再启动恢复。
- 项目详情：暂停会停名下 Launchpad 应用和 KubeBlocks 数据库；启动/重启同理。对象存储和定时任务不动。应用和数据库都停了之后，聚合状态是「已暂停」。
- 删除 / 重启进行中不能连点出两次请求。
- 切工作空间后，按钮打到的是新空间，不是旧空间。
- 项目列表、Launchpad 应用列表能勾选多条；操作栏可暂停/启动/重启/删除选中项。暂停只打未停的，启动只打已停的。
- 批量删除一次确认；项目合计写清会带走的应用/数据库/存储桶；属于项目的应用只删应用。
- 批量里某一条失败，其它已成功的不被撤销；失败名单可见。
- Launchpad 之外、数据库 tab、存储 tab 没有批量。切 tab / 切工作空间后选择消失。
