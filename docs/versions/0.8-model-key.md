# Helios 0.8 — 自己的模型 Key

相对 [vision](./vision.md) / [0.7](./0.7-update.md)：对话模型允许用户接入自己的 DeepSeek API Key。没填则维持现状（工作空间 AI Proxy）。

包版本 `0.8.0`。

## 约束（已拍板，不要再改）

- **覆盖，不是替换。** 有 Key：官方 DeepSeek。没 Key：登录就能聊，走现在的 AI Proxy（自动 `helios` Key，DeepSeek Flash 优先，否则 Gemini 3.5 Flash）。
- **只接 DeepSeek。** 不接 ChatGPT / Codex OAuth、不接 OpenAI 官方、不接其它厂商。
- **型号锁死。** 接入自己的 Key 时强制 `deepseek-v4-flash`。没有模型选择器，设置里不能改型号。
- **入口是设置，不是 AI Proxy。** 侧栏 AI Proxy 仍是 Sealos 网关（用户给自己的应用开 Key），本版不改那一页。
- 不走 Vercel AI Gateway。密钥只进主进程和 eve 子进程环境变量；落盘后渲染进程只看到打码。

## 用户看见的流程

头像（侧栏底）仍是入口。页标题由「用户信息」改为 **设置**。头像 `title` 同步改成「设置」。

一页两块，不要新开导航、不要 modal：

1. **账户**：现有字段原样（工作空间、区域、API Server、命名空间、登录时间、kubeconfig）。**退出登录**仍在这块底部。
2. **模型**：
   - 一句说明：对话固定使用 DeepSeek V4 Flash。未接入时走工作空间的 AI Proxy。
   - 密码框：DeepSeek API Key。旁链到 [DeepSeek 开放平台](https://platform.deepseek.com/api_keys)（系统浏览器打开）。
   - 未接入：框是空的，主按钮「保存」。
   - 已接入：不回填明文，展示打码（`sk-…` + 末 4 位）。可再贴一把新 Key 覆盖。另有「清除」。
   - 保存失败（空、校验失败、网络）：Key 不落盘，eve 不重启，页上显示错误。
   - 保存或清除成功：已登录则重启 eve（和切工作空间同一套路）。进行中的一轮丢掉，不假装还在。

设置页不要显示资源快照的「更新于 …」。

退出登录 **不清** 这把 Key。切工作空间也不清——DeepSeek 账户是人的，不是 Sealos namespace 的。

## 工程落点

做事在 Electron **主进程**。渲染进程不直连 DeepSeek。

### 落盘

`~/.helios/model.json`，模式 `0600`，写入用临时文件再 rename（与对话 JSON 同一套路）：

```json
{
  "provider": "deepseek",
  "apiKey": "sk-…"
}
```

没有该文件、读失败、或缺 `apiKey`：视为未接入。`provider` 不是 `deepseek` 也视为未接入（本版只有这一种）。

### 启动 eve 时选哪条路

`startAgent` 里、现有 `ensureHeliosKey()` 之前：

1. 已接入 → `endpoint = https://api.deepseek.com/v1`，`apiKey` 用文件里的，`model = deepseek-v4-flash`。**不要**再调 AI Proxy。
2. 未接入 → 维持 `ensureHeliosKey()`。

eve 仍只认环境变量 `HELIOS_AI_BASE_URL` / `HELIOS_AI_KEY` / `HELIOS_AI_MODEL`。`apps/eve/agent/agent.ts` 不必为 0.8 改协议；没有自己的 Key 时行为与 0.7 相同。

官方端点带 `/v1`，与现在 AI Proxy 的 `https://aiproxy.{region}/v1` 同一形态。`@ai-sdk/openai-compatible` 已经在用。

### 校验

保存时主进程 `GET https://api.deepseek.com/v1/models`，`Authorization: Bearer <key>`，超时 15s。

- HTTP 2xx：落盘，已登录则 `startAgent()`。
- 401 / 403：错误「密钥无效」。
- 其它 HTTP / 超时 / 断网：错误「无法连接 DeepSeek」。
- 空或纯空白：错误「请填写 API Key」，不发请求。

不要用一次 completion 做校验（费额度）。不要把 Key 打进 `console.log`。

### IPC / 类型

`HeliosApi` 增加三条，渲染进程拿不到明文：

- `getModelSettings(): Promise<{ configured: boolean; hint?: string }>`
  - `configured === true` 时 `hint` 为打码，例如 `sk-…7f2a`（不足 4 位就整段打码，不要把短串当明文送回去）。
- `saveDeepseekKey(key: string): Promise<void>`
- `clearDeepseekKey(): Promise<void>`

preload / `shared/types.ts` / `main/index.ts` 一并接上。channel 名跟现有 `helios:*` 风格。

### 包版本

根、`apps/electron`、`apps/eve` 三个 `package.json` 的 `version` 改为 `0.8.0`。`docs/versions/vision.md` 版本记录与「模型凭证」架构段改成上面这套覆盖口径。

## 本版明确不做

- ChatGPT / Codex 登录、OpenAI 官方 Key、多厂商 BYOK
- 模型选择器、改 thinking 开关、改 eve 的 context window
- 把 Key 做成 AI Proxy 页的一项
- 退出登录或切工作空间时清 Key
- 没 Key 时禁止对话（那是替换，已否决）
- 改 0.2 对话、0.3 模板、0.4 操作、0.5 拓扑、0.6 数据库、0.7 更新探测

## 验收

- 未接入：登录后对话与 0.7 一样，仍会在该工作空间确保 `helios` Key。
- 设置里贴一把有效 DeepSeek Key 并保存：打码展示；eve 重启后 `HELIOS_AI_BASE_URL` 为 `https://api.deepseek.com/v1`，`HELIOS_AI_MODEL` 为 `deepseek-v4-flash`；此后启动 **不再** 调 AI Proxy 建 Key。
- 无效 Key：不落盘、eve 不重启、页上有错误。
- 清除：文件去掉（或不再算已接入）；已登录则 eve 重启并回到 AI Proxy 路径。
- 退出登录再登录、切工作空间：Key 还在，仍走官方 DeepSeek。
- 设置页标题是「设置」，没有「更新于」；账户块与退出登录还在。
- AI Proxy 页外观与接口不变。
- `npm run typecheck` 通过。
