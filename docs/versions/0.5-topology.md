# Helios 0.5 — topology

相对 [vision](./vision.md) / [0.1](./0.1-baseline.md) / [0.4](./0.4-operate.md)：项目详情里应用、数据库、对象存储从三列清单改成一张拓扑画布，画出它们之间已经存在的关系。

已完成，2026-08-15。包版本 `0.5.0`。

## 相对 0.1 的缺口

0.1 项目详情按 kind 分区：公网入口、应用、数据库、对象存储、定时任务、配套资源。同属一个 Instance 标签，但用户看不见「这个应用连的是哪一个库」。Railway 那种画布的价值是边，不是把卡片摆到格子上。

## 模型

- **节点**：Launchpad 应用（含项目里的非 Launchpad 工作负载）、KubeBlocks 数据库、对象存储桶。公网 URL 不是独立节点——它是应用节点的副标题（点开外开）。持久卷不是独立节点——有 PVC / volumeClaimTemplates / 库的 storage 时画在节点页脚，和 Railway 的 volume 条同一概念。
- **边**：应用 → 数据库 / 存储桶。只画能从工作负载 env **证实**的引用。不发明 Sealos 的「拓扑 API」，Instance CR 也没有这份图。
- **证实规则**（主进程读已有 Deployment / StatefulSet，明文不进渲染进程）：
  1. env / envFrom 的 secret 名 = `{db}-conn-credential`，或 `{db}-` 前缀且含 `conn-credential` / `-account-`（Redis / Mongo 的 account secret）。
  2. env 字面量含该库的 in-namespace host 片段（`{db}-postgresql` / `{db}-mysql` / `{db}-mongodb` / `{db}-redis` 等 skill 口径）。
  3. 桶：字面量等于 CR 名或 `status.name`；或 secret 名以 `object-storage-key-` 开头并以 `-{bucket}` 结尾（`object-storage-key` 是账号级共享密钥，单凭它不能连到每一个桶）。
- **回退**：整个项目一条边都推不出来、且只有一个应用时，把这个应用连到名下全部库和桶。这是商店模板的常态（配置文件写死、不走 env）。多应用项目不做这个回退，避免瞎连。
- **定时任务、配套资源**：仍是列表。它们不是拓扑上的一等节点。

## 用户看见的流程

项目详情：统计条、异常 Pod 横幅保留。下面那三列（加公网入口）换成一块浅色点阵画布。

- 应用在上、依赖在下；虚线正交边、箭头朝下。
- 应用节点：名字、公网域名（无域名则镜像）、状态点、副本；有盘则页脚。点卡片进已有应用详情；点域名外开，不进详情。
- 数据库 / 存储桶：没有详情页，点了不跳。库显示引擎与状态；桶显示策略与实际桶名。
- 不是编辑器：不能连线、不能删节点、不保存位置。节点多了可以拖动画布平移；滚轮继续滚详情页，不在画布上缩放。
- 只有定时任务、没有应用/库/桶：画布不出现，下面列表照旧。

## 工程落点

- 类型：`ProjectLink`（应用→库/桶）、`VolumeHint`（节点页脚）。`ProjectDetail.links` 由主进程填；列表快照的 `AppWorkload` 不带 volume。
- 主进程 `apps/electron/src/main/sealos/topology.ts`：从已拉取的 Deployment / StatefulSet env 推断边。不新增 IPC、不新增 Sealos 请求。`fetchProjectDetail` 同时给应用/库挂 `volume`。
- 渲染：`ProjectTopology` 用 `@xyflow/react`（renderer 的 devDependency，vite 打包）。浅色点阵、Helios 卡片描边。应用在上、库和桶在下，一行最多 4 个，多了换行。`preventScrolling={false}`、`zoomOnScroll={false}`，避免嵌在详情里吞掉滚动。画布 `-webkit-app-region: no-drag`。
- **点击必须走 React Flow 的 `onNodeClick`**。xyflow 在节点 `selectable=false`、`draggable=false`、又没有 `onNodeClick` 时，给 wrapper 设 `pointer-events: none`，卡片内部的 onClick（含公网链接）全部点不透。点应用节点进已有应用详情；点域名 `stopPropagation` 后外开，不进详情。不要改回只在卡片 div 上绑 onClick。
- 根和 `@helios/electron` 的 `package.json` version 改为 `0.5.0`。

## 本版明确不做

- 数据库 / 存储桶详情页
- 应用之间的边（worker 共用镜像那种）
- 把定时任务、Secret、PVC 画成节点
- 持久化节点坐标、小地图、画布上的暂停/删除
- 改 0.2 对话、0.3 模板部署、0.4 操作按钮

## 验收

- eaglercraft 这类单应用无库：画布上一个应用节点，域名在副标题。点卡片进应用详情；点域名外开浏览器、不进详情。不再出现空的「数据库」列。
- 应用节点悬停是指针；点下去一定进该应用详情（回归：去掉 `onNodeClick` 会全画布点不动）。
- 带 pg/redis 的模板：应用在上、库在下，有边。库的页脚有容量（有的话）。
- 带对象存储且 env 按 skill 注入 `object-storage-key-…-{bucket}`：有应用→桶的边。
- 多应用且 env 对不上：节点在，边可以没有。不要给每个应用连上每一个库。
- 详情页在画布上滚轮仍能滚页面。15 秒刷新后节点还在、边还对。
- 顶栏删除 / 重启 / 暂停 / 启动、面包屑、配套资源列表行为与 0.4 相同。
