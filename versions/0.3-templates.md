# Helios 0.3 — template deploy

相对 [vision](./vision.md) / [0.1](./0.1-baseline.md) / [0.2](./0.2-agent-chat.md)：模板页的「部署」真正把商店模板装进**当前工作空间**，不再跳出到控制台。

已完成，2026-08-14。包版本 `0.3.0`。

## 相对 0.1 的缺口

0.1 模板页已经能浏览 sealos.io 商店目录。卡片上的「部署」打开 region 控制台的 `openapp=system-template` 深链。浏览器会话 ≠ Helios 这份 kubeconfig，点完当前 Workspace 里不会出现项目。0.1/0.2 把「改走 agent」留到了后面。

那不是最短路径。用户在卡片上已经选好了模板，分类做完了，不需要模型再 `store-list`。Sealos 对商店模板就是一次带 kubeconfig 的 POST。对话仍留给「开始」里的自然语言部署，以及项目起来之后的排障。

## 三次「完成」

| 时刻 | 含义 | 用户看到 |
|---|---|---|
| **受理** | Template API 201，Instance CR 已写入当前 ns | 离开模板页，打开该项目详情 |
| **就绪** | 应用 / 数据库变成运行中 | 详情顶栏「启动中」→「运行中」（已有 15s 轮询） |
| **可访问** | 公网 URL 返回真页面 | URL 可点；不挡在跳转前面 |

导航只等受理。不要在 201 之后 toast「部署成功」——那时 pod 往往还在拉镜像。成功只出现在详情自己变成「运行中」、URL 能打开的时候。

## 用户看见的流程

1. 点卡片「部署」。该按钮立刻变「提交中」并禁用，防连点。其它卡片照常可点。不弹「确认部署吗」——点这张卡的按钮已经是确认。工作空间以侧栏胶囊为准，不必再选。实例名 `{templateName}-{random8}`，不问用户（k8s DNS 子域、≤63；超长则截短模板段）。
2. 主进程 GET `https://template.{region}/api/v2alpha/templates/{name}`，看 `args`。只处理 `required: true` 且没有非空 `default` 的项。绝大多数模板这一步是空的，用户无感。
3. 有必填（API Key、邮箱这类只有用户知道的值）：**卡片上展开一小条**，只问这几项；名称含 key / secret / token / password 的用 password。填完同一颗按钮变成「部署到 {当前工作空间名}」。不要抄控制台那整页表单（可选环境变量、规格、README、价格盒都不做）。
4. 配额：GET 会带 `quota`（cpu 核、memory/storage GiB）。和侧栏同源的 namespace `ResourceQuota` 比较；不够就停在卡片上报「配额不足」，不发 POST，也不偷偷把 CPU/内存改小。GET 没有配额数字时不要因此拦截。
5. POST 失败：人不走，错误钉在这张卡片上。
   - 400 缺参 → 展开那一小条
   - 403 / 余额不足 → 配额或余额文案
   - 409 → 先确认当前 ns 里这个 instance 是否已经落地（create 不原子，409 有时其实成功了）；有则当受理跳转。没有则换新随机名再 POST 一次。第二次仍失败再报错。
6. POST 201：切到「项目」tab，打开这个实例的详情（现成的 `openProject`）。刷新资源快照，让列表里立刻能看到它。详情已有：聚合状态「启动中」、组件分区随轮询出现、Ingress 一旦有就列出公网 URL（未就绪点开 503 是预期，不要藏 URL）、异常 Pod 横幅。不新做部署进度页，不自动跳「开始」，不在聊天里复述 yaml。

## API（对着 Sealos 源码，不发明）

源码以本机 `/Users/che/Documents/GitHub/sealos/frontend/providers/template` 为准（没有则按 `.cursor/rules/sealos-source.mdc` 补 sparse clone）。实现时对照，不要凭这份摘要硬编字段。

- **GET** `https://template.{regionDomain}/api/v2alpha/templates/{name}`
  - 实现：`src/pages/api/v2alpha/templates/[name].ts`
  - 不鉴权（公开目录详情）
  - 200：`{ name, args, quota, ... }`。`args` 是 `Record<string, { description, type, default, required }>`（即 `template.spec.inputs`），不是数组。
- **POST** `https://template.{regionDomain}/api/v2alpha/templates/instances`
  - 实现：`src/pages/api/v2alpha/templates/instances.ts`
  - 鉴权：`Authorization: encodeURIComponent(kubeconfig)`（与 `sealos-api.py deploy-store`、applaunchpad 监控同一套）
  - body：`{ name, template, args? }`。`template` 用目录里的 `templateName`，不是展示名、不是 slug（除非二者碰巧相同）。
  - 201：`{ name, uid, resourceType: "instance", args, resources }`。跳转用响应里的 `name`。
  - 错误体：`{ error: { type, code, message, details? } }`（v2alpha）。按 HTTP 状态 + `error.code` 映射到卡片文案，不要把整段 JSON 丢给用户。
- 409 落地确认：直读当前 ns 的 `instances.app.sealos.io`（Helios 项目列表已经这样读），不要改走 `template.{region}/api/instance/list`。

kubeconfig 指向哪，资源就进哪。没有「部署到哪」这一步。

## 工程落点

做事在 Electron **主进程**，不经过 eve。看见就是现有项目详情。

- 主进程：在 `apps/electron/src/main/sealos/templates.ts`（或同目录新文件）封装 GET + 配额预检 + POST + 409 重试。IPC 对渲染进程暴露两档即可：取详情（args/quota）、部署（templateName + args → instanceName）。超时按 Sealos 侧 120s 量级，不要用目录拉取那 15s。
- 类型 / preload / `HeliosApi` 一并补上。`TemplateInfo.deployUrl` 可以留着，按钮不再用它。
- 渲染：`TemplatesTab` 接上提交态、必填条、卡片错误；成功回调让 `ResourcesScreen` 走已有 `openProject(name)` 并刷新快照。工作空间展示名用 `status.workspaceName`。
- 卡片标题仍可外开 sealos.io 详情（那是文档，不是部署）。

从「开始」打字「部署 n8n」仍然走 agent Path A。两条入口汇合到同一个 Instance CR，项目列表不分叉。

落地时相对上文的三处对齐，不改交互：

- POST **200 与 201** 都当受理（与 `sealos-api.py deploy-store` 相同）。
- 模板 host 优先 `auth.json` 的 `region`，再回退 kubeconfig hostname（避免 `apiserver.*` 拼错）。
- 工作空间名沿用侧栏回退链：`workspaceName` → `workspace` → `Sealos 工作空间`。

## 验收

- 点一个无必填项的模板：按钮进入提交中，随后落到「项目」详情，侧栏当前工作空间下能看到这个实例；浏览器不会被打开。
- 点一个有必填项的模板：先出现卡片内输入，不发 POST；补全后按钮文案含当前工作空间名，提交后同上。
- 配额不够：卡片报错，ns 里没有新 instance。
- 同一张卡片连点不会创建两个实例；另一张卡片在第一张提交中仍可点。
- 切工作空间后再部署，实例出现在新空间，不出现在旧空间。
