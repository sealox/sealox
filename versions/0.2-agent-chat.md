# Helios 0.2 — agent chat

相对 [vision](./vision.md) / [0.1](./0.1-baseline.md)：0.1 已经能把话丢给本地 eve；本版把「开始」做成可用、好用的 agent 对话——能开多条、能回来看、能看懂回复。

## 相对 0.1 的缺口

- 全程只有一条 eve session，挂在主进程内存里。没有「新对话」，没有历史列表。刷新/重启/切工作空间（会重启 eve）后 UI 对话清空。
- eve HTTP **没有** session 列表接口。可续聊的只有 `sessionId` + `streamIndex` 游标；**全文必须 Helios 自己存**（eve 客户端文档：cursor 不是 transcript）。
- 思考过程已是 `<details>`，工具活动是旁边另一份列表；reasoning 和正文都是纯文本。`white-space: pre-wrap` 把 markdown 当字面量显示。
- 聊天区 `max-height: 52vh`，有内容时仍是 hero 小窗，不是占满内容区的对话。
- 没有停止本轮。部署类 turn 会在本机跑 bash/docker，只能干等。
- `ask_question` 只显示「提问」活动行，没有作答入口；agent 在 `session.waiting` 停住，用户无感。

## 对话历史侧栏

ChatGPT 那一套：**默认收起，只留一个展开 icon**；展开后是一条条用户–AI 对话，可点开切换。

这不是现有那根 256px 资源侧栏。资源导航继续服务全 app，本版不把它改成对话列表。对话历史只出现在「开始」页：

- 默认：内容区左上角一个历史 icon，不占列。
- 展开：从左侧滑出抽屉，盖住聊天内容区，**不动**资源侧栏。再点 icon / 点抽屉外收起。
- 列表按当前工作空间过滤；切空间只看到该空间下的对话。
- 标题默认用该条对话的第一条用户消息，截断即可。不另做重命名编辑器。

## 新对话与切换

- **新对话**：清当前 UI，`POST /eve/v1/session` 开新 session（旧的可 `reset`）。空会话回到居中标题 + 输入框。
- **切换**：先渲染落盘全文；后续发送 `attach` 该 `sessionId`。attach 失败（进程没了、session 已 reset）则 UI 仍显示历史，并开新 session——模型侧上下文可能断，不要假装还在。本版 **不做**把 Helios 历史回放进新 session。

## 落盘（JSON 文件，不上 SQLite）

对话是一份文档（标题 + 消息树），不是要 JOIN 的表。本版访问只有列表、打开、每轮覆写、删除。单用户桌面，不做搜索。SQLite 的收益（查询、并发）用不上，Electron native 模块还要跟 ABI 打包，不值得。以后真要全文搜索或更复杂的本地状态再迁；文件里就是完整 JSON，迁移成本低。

目录跟现有 `~/.helios/` 约定：

```
~/.helios/chats/<workspaceId>/index.json
~/.helios/chats/<workspaceId>/<conversationId>.json
```

- `index.json`：侧栏用的轻量列表（id、title、updatedAt）。不要为了画列表去读每条全文。
- `<conversationId>.json`：该条全文（id、title、workspaceId、eveSessionId、streamIndex、messages、createdAt、updatedAt）。消息字段以实现为准，须能还原用户原文、assistant 正文、按发生顺序排列的 thinking / 工具 trace。
- 写入用临时文件再 rename，避免写到一半崩掉留下半份 JSON。
- 主进程读写；渲染进程不碰磁盘。

一条 Helios 对话 ↔ 一条 eve `sessionId`。多对话 = 多个 session。切工作空间仍会重启 eve（0.1）。历史以 Helios 落盘为准；活 session 能 attach 就续，不能就开新的。

## 思考链按发生顺序拆开

不要把整轮 reasoning 和全部工具揉成一条长链。Agent 实际是：想一段 → 调工具 → 再想一段 → 再调工具 → 最后给正文。UI 按这个时间线画，thinking 和工具是同一条有序列表里的不同行：

- 每一段模型 reasoning（eve 的一个 `stepIndex`）是一行 **thinking**：默认收起，只显示标签 `thinking`；点开才看这一段。生成中也不自动展开。
- 每个工具调用（`load_skill` / bash / 读文件 / 搜索…）是独立一行，插在相邻两段 thinking 之间。
- 落盘为有序 `trace`（`thinking` | `activity`）。旧 JSON 若仍是整段 `reasoning` + `activities` 列表，打开时仍能看（思考在前、工具在后）；新轮次按交错写入。
- 工具细节继续截断，不把可能含密钥的全文倒进 UI（vision 已定，本版保持）。
- Flash 类模型常常不吐 reasoning：这时时间线可以只有工具行。这是预期，不是缺 UI。

## 渲染 agent 的 markdown

只渲染 **assistant 正文**（思考链里的 reasoning 按纯文本或轻量 markdown 即可，不要做成第二份文章）。

- 标题、列表、加粗、链接、代码块。
- 流式过程中对不完整 markdown 做尽力渲染，允许短暂难看。
- 链接用系统浏览器打开（Electron，不在 app 内跳）。
- 不执行回复里的 HTML。
- 用户气泡保持纯文本。
- assistant 消息可复制渲染前的原文。

## 有消息时的版式

空会话保留居中 hero。一旦当前对话有消息：消息区占满「开始」内容区，输入框钉在底部。去掉 52vh 小窗。贴底时才跟新消息；用户上翻后不要强行拉回去。

## 停止与提问

- **停止本轮**：`POST /eve/v1/session/:id/cancel`，等流上的 `turn.cancelled`。eve 前端 `stop()` 只断客户端、服务端 turn 继续跑，不能当产品语义。本机 docker/kubectl 被 cancel 后是否真停，实现时对 eve 核实；未核实前 UI 不承诺「机器已经停了」。
- **`ask_question` 作答**：流里的 `input.requested` 画成当前轮的选项/输入，回答走 eve 的 `respond`。没有这一步，部署对话会无声卡死。

主进程是 eve 的唯一客户端：在 0.1 的 session/stream 上补 `POST .../cancel` 与 HITL `respond`。路由和字段以 eve 源码/docs 为准。渲染进程只拿已经投影好的消息（文本、思考链、活动、错误、待回答的提问），自己画 markdown。

## 本版明确不做

见 vision。另外不做：SQLite / 其它数据库；对话搜索、导出、分享；改资源侧栏的信息架构；拖文件夹 / 粘贴 git 作为部署入口（仍是 0.1 未决）；模板页「部署」按钮改走 agent；编辑已发送消息、重新生成、把 Helios 历史回放进新 eve session；模型选择器（仍按 vision：DeepSeek Flash，否则 gemini-3.5-flash）；渲染进程直连 eve / 换用 `useEveAgent`（CORS 和 `file://` 的原因没变，仍主进程 HTTP + IPC）。

## 验收

- 默认看不到对话列表，只能看到展开 icon；展开后能切换、能新开；抽屉不挤走资源侧栏。
- 杀 App 再打开，同一工作空间下历史还在；点进去看得到上次的用户话和已渲染的 markdown 回复。
- 每段 thinking 默认收起，只显示 `thinking`；点开只看到该段。工具是独立行，夹在 thinking 之间。
- 带列表/代码块/链接的回复按 markdown 呈现，链接外开。
- 空会话仍是「今天想开发点什么？」；有消息后是满屏对话 + 底栏输入；上翻不被新 delta 拽走。
- 生成中可停止；agent 提问时能在当前轮作答。
